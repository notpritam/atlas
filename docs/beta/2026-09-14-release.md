# FoundKeep production test release — 14 September 2026

This release consolidates the friends-beta branch and the approved interface updates on `main`. It is suitable for Pritam's production web/extension end-to-end testing. It does not establish complete friends-beta readiness across paid processing and native distribution.

## Shipped source and web behavior

- Consistent FoundKeep display branding, self-hosted Inter, shared theme/control/card tokens, and published Font Awesome platform icons.
- Simplified landing/auth entry, authenticated home redirect, animated FAQ, compact footer, and shared Free/Pro comparison.
- Persistent dashboard shell and query cache, URL-driven navigation, global Cmd/Ctrl+K, direct account settings, content skeletons, and rounded expandable capture dialogs.
- Shared collection filters, dark-mode contrast, sticky public collection search/topics/view controls, and readable Apps & devices links.
- A final review fix prevents a delayed landing session response from overriding navigation after leaving the page.
- Extension 1.7.2 retains the existing production signing key/ID and separate dev identity/storage/origin. Chrome Web Store publication is separate from the signed self-hosted release and manual ZIP.

## Verification

Fresh pre-merge checks passed: 433 Bun tests, 66 extension tests, 26 customer-flow tests, 17 legacy landing tests, mobile typecheck, and Next build/typecheck. The Next integration batch passed 24 cases; its optional deferred-export security case was then enabled and passed. The final navigation/auth batch passed all 14 cases, including the delayed-response regression and deferred-export guard. Independent code review found no remaining critical security, data isolation, billing, or platform identity regression in the pending changes.

Production's running media/source/processing code matches this checkout. Its existing immutable backend release is retained; deployment must not overwrite customer data, install demo fixtures, or copy dev credentials into production. Production web builds target port8790 and must never embed Paddle sandbox configuration. Existing Android APK5 and checksum must be retained when replacing the website release.

## Readiness limits

- Production currently has no OpenAI key or live billing credentials. Managed Pro processing is therefore unavailable until an intended provider key and legitimate Pro access path are configured. The beta access choice is pending; no complimentary grant, provider key transfer, or paid checkout is assumed.
- Browser capture retains readable article/blog text and available tweet/page content. Original local file uploads retain their bytes.
- The guarded downloader and private video playback integration already exist for supported public X, Instagram, YouTube, and direct MP4 sources. Earlier live X/Instagram samples succeeded. Source URLs are retained alongside stored files.
- YouTube video downloads are not broadly verified: the previous live sample was refused upstream, and the current runtime rejects adaptive-only/protected/live/unsupported media. Saved links remain intact and failed downloads do not claim success.
- Android APK5 and TestFlight build21 predate the latest native sharing/processing-observer fixes. Updated signed artifacts and physical-device end-to-end checks remain separate release gates. External TestFlight access also requires tester setup and beta review.
- Public App Store/Google Play release and invitations to friends are not part of this production test deployment.
